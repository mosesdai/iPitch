# 12 · 行业大盘与口径纪律（v1.6）

> **本章的诚实声明（放在最前面）**：
> 本轮 **未取到可信一手口径** 的中国新能源市场规模、渗透率、家庭 SUV 细分盘、体育营销市场规模。
> 因此本章 **不给这些数字**，改为提供：**① 可用的公司自身锚（A）② 口径纪律 ③【待核实】清单 ④ 会面替代打法**。
> **这不是偷懒，是纪律**：会面里报一个来源不明的大盘数，被追问一次就全线失信。

---

## 0. 口径纪律五条

1. **不同来源的口径不得加总**（乘用车 vs 新能源 vs 纯电，各家统计范围不同）。
2. **公司 A 源优先**：能用 NIO 自己的公告数字说明的，绝不引外部估算。
3. **竞品月度交付是 C 级**，与 A 级并列时必须标注（见 `04`）。
4. **自算值必须写「自算」**，并给出被除数与除数。
5. **预测一律宁空**：不做全年推算、不做 CAGR、不做份额预测。

## 4. 「没有大盘数」怎么开会（替代打法）

| 传统打法（依赖大盘） | 本案替代打法（依赖客户自身数据） |
|----------------------|----------------------------------|
| 「市场有多大，你们该投多少」 | 「你们三条线上个月分别是 21,908 / 11,743 / 6,946，方向不一样」 |
| 「渗透率还有空间」 | 「乐道 5月 12,029 到 6月 11,743，峰值没变台阶」 |
| 「行业都在投体育」 | 「你们已经投过两种形态：姚明和申花」 |
| 「我们能覆盖 X 亿人」 | 「我们能补的只有三样：架构、青年触点、外部公信力」 |

**结论**：本案的说服力 **完全来自客户自己的公告数字**。这反而是更强的位置——**没有一个数字是他们可以质疑来源的。**

## 6. 数字口播安全版（30 秒 · 会面可原样用）

> 「我只用你们自己公布的数字：
> 二季度 **107,658** 台，同比大约 **五成** 增长；
> 六月三条线分别是 **21,908 / 11,743 / 6,946**；

## 9. 加厚 · 为什么「补一个大盘数」反而更危险

诱惑很大：随便引一个咨询报告的市场规模，材料看起来就完整了。本案拒绝，理由有四条：

| 理由 | 说明 |
|------|------|
| **一问就崩** | 对方问「这个数含不含出口 / 含不含商用车」，答不出 → 全篇失信 |
| **口径互斥** | 批发 / 零售 / 上险 / 含出口，四种口径可以差出很多，加总即错 |
| **与决策无关** | 市场多大，不改变「体育预算有没有 owner」 |
| **会变成催单** | 「市场这么大你们该投」= 跟风逻辑，撞秦力洪反爆款红线 |

**关键洞察**：在本案里，大盘数 **不是缺失的论据，而是被主动排除的论据**。这个区别必须在材料里写清楚，否则会被误读为研究不完整。

---

## 10. 加厚 · 「只用客户自己数字」的三个附带好处

1. **来源不可争议**：所有数字都是对方自己发的公告，质疑来源等于质疑自己。
2. **可当场演算**：+49.4%、−2.4%、+22.7% 都是一次除法，手机就能验。
3. **姿态正确**：用对方的数字讲对方的结构，比用行业数字教育对方要谦逊得多。

**副作用**：材料会显得「数字很少」。这需要在 ONE_PAGER 与本章里 **主动解释** —— 少不是懒，是纪律。

---

## 11. 加厚 · 如果客户主动要行业数据怎么办

| 场景 | 答法 |
|------|------|
| 「市场有多大？」 | 「口径太多，我不想给你一个我自己不敢背的数。你们内部用哪个口径，我按你们的口径来。」 |
| 「体育营销行业多大？」 | 「各家统计差异很大，我只能给判断，不能给统计。」 |
| 「同行都花多少？」 | 「没有可信汇总，我不评论别家预算。」 |
| 「那你们凭什么说该做？」 | 「不凭行业大小。凭你们六月三条线在往三个方向走。」 |

**最后一条是本章的最终武器**：把论证的地基从「行业」搬到「客户自身结构」上。地基一换，所有关于大盘数的追问就失效了。

---

## 12. 加厚 · 何时才该补大盘数

不是永远不补。三种情况下必须补：

| 情况 | 需要什么 |
|------|----------|
| 进入 **报价阶段** | 需要行业价格带作参照（单一来源 + 明示口径） |
| 客户 **内部立项** 需要外部数据 | 按客户指定口径补，署名来源 |
| 做 **多年框架** | 需要品类趋势（本轮不涉及） |

**当前阶段（第一次会面前）三种都不适用** → 本轮不补是正确的，不是遗漏。

## 13. 加厚 · 口径纪律的通用检查表（可复用到其他案子）

- [ ] 每个数字有 **来源 + 时间锚 + 级别**
- [ ] 每个派生数字标 **自算** 并给出算式
- [ ] 不同口径的数字 **不出现在同一个加总里**
- [ ] 季度数与月度数 **不放在同一个增长率里**
- [ ] 公司口径与行业口径 **不混句**
- [ ] 未披露的一律写 **「未披露」**，不写「约」「预计」
- [ ] 媒体转载标 **C** 且不进刀
- [ ] 预测一律 **宁空**

**这张表就是本案 `research/` 的全局质检标准**。任何一章新增内容后，都应回来对一遍。

## 14. 加厚 · 「厚度」应该怎么定义

本案对标 nestle / xiangpiaopiao 的冰山厚度。但厚度不该只按字数算。给一个四维定义：

| 维度 | 本案自评 | 依据 |
|------|----------|------|
| **可回验密度** | 高 | 所有关键数字有来源 + 时间锚 + 级别；派生数字有算式 |
| **反证密度** | 高 | `../ifalsify_report.md` 10 条反证，支持:反证 ≈ 0.4:1 |
| **缺口显式度** | 高 | 七类【待核实】+ MEDDIC 四空两半 + 「不需要 vs 待核实」区分 |
| **不说清单占比** | 高 | `09` 分四层，且随全文镜像对客户公开 |
| 字数量级 | 见 `README.md` | 与 nestle 同量级 |

**为什么把字数放最后**：一份两万字的资料堆积，承重能力可能低于一份一万字但每条都能回验的研报。**厚度是承重，不是体积。**

## 15. 加厚 · 本案与 nestle 案在「大盘」处理上的差别

| 项 | nestle 案 | 本案（nio） |
|----|-----------|-------------|
| 大盘数据可得性 | 有可引的第三方口径 | **本轮未取到可信一手** |
| 处理方式 | 多口径并陈、禁止加总 | **主动排除 + 替代打法** |
| 说服地基 | 行业 β × 公司 α 对照 | **纯公司 α**（客户自己公布的数字） |
| 风险 | 口径被追问 | 材料显得「数字少」 |
| 缓解 | 明示口径与来源 | 本章 §9–§11 主动解释为什么少 |

**方法论结论**：当大盘不可得时，正确做法不是降低标准去引不可靠的数，而是 **换一个更硬的地基**。本案证明这个地基是够用的——因为客户自己的三个月交付曲线，已经足以支撑一条完整的张力。

## 16. 加厚 · 会面中关于「数字少」的自我说明（可照念）

> 「你们会发现我今天带的数字很少。
> 那是因为大盘口径太多，我不想给你一个我自己不敢背的数。
> 我只用你们自己公告里的：Q2 107,658、六月 21,908 / 11,743 / 6,946。
> 这些你们随时能核，我也随时能算给你听。」

**效果**：把「数据少」从弱点变成 **纪律的证明**。这段话在 CFO 频道尤其有效。

## 17. 加厚 · 最终收束

> 本章的存在，是为了让整份研报在 **最诱人的地方**（编一个漂亮的市场规模）**没有编**。
> 一份研报的可信度，取决于它最薄弱的那一句话。本案选择让最薄弱的地方是「我们不知道」，而不是「据估算」。
